# PGM 开发测试

PGM 支持通过 `tools/build.py --pgm` 显式启用，当前仍是开发测试功能，未包含在 v0.1.2 Release 中。

使用固定依赖和原有 408 MHz / A68K 组合构建：

```powershell
python -X utf8 tools/build_pgm.py --toolchain "你的工具链/bin" --host-cc "你的gcc.exe"
```

输出 `dist/H1ArcadePGM.bda` 和对应构建记录。它也保留原有 Neo Geo 支持。

首批目标是《三国战纪》一代 `kov` V117。其他 PGM 游戏、改版以及 PGM2/PGM3 尚不支持；不能只重命名 ZIP 来变成受支持版本。

将自己提供的 `kov.zip` 和 `pgm.zip` 放在 H1 的 `A:\ARCADE`，打开带 PGM 支持的街机应用选择游戏 ZIP。首次在设备上生成同目录 `.h1pgm` 文件，后续复用缓存。若 A 盘写缓存失败且临时文件已成功清理，会尝试建立 `B:\ARCADE` 并把缓存写入 B 盘；下次仍选择原 ZIP 即可复用它。原 ZIP 保留。已有缓存或临时文件不会被覆盖。

缓存约 64.2 MiB，包括原始程序、图形、声音及每个 4 KiB 页的 CRC。转换按块解压、验证成员 CRC，写完后读回检查数据和页校验表，再以同目录改名提交。转换失败或取消会清理本次临时文件。

68000 复用 A68K；PGM 内存总线单独处理，不使用 Neo Geo 的 RAM/ROM 快速映射及轮询 HLE。Z80 复用现有解释器，端口改接 ICS2115。KOV ASIC28 使用上游 HLE；程序解密从固定 FBA 源码生成，未更改上游 checkout。

图形与声音 ROM 按需读取，运行时用 2 MiB 的四路页缓存，命中前核对页标签。按用户要求，播放时不计算页 CRC，BIOS/程序加载也不再校验区 CRC，不分配或读取页 CRC 表；现有 H1PGM1 文件可直接复用。文件读取失败及格式、尺寸、地址范围检查仍保留。首次 ZIP 转换的成员识别、CRC 和转换读回检查不在逐帧路径中。

背景 5-bit 图块采用 1 MiB 解码缓存；文字层缓存 4-bit 解码结果及透明行标记。精灵把掩码及三像素打包颜色解成可复用的调色板索引，默认使用 8 MiB 循环缓存，分配失败时尝试 4/2/1 MiB。索引不依赖调色板、翻转或缩放；每个精灵的水平缩放、翻转及裁剪坐标只计算一次。原始 ROM 读游标仍核对页标签，避免另一条流换页后误用旧指针。完全不可见的精灵不绘制；图层优先级、翻转、缩放与行滚动保留。

调色板写入时预计算与旧 RGB565 输出完全一致的屏幕颜色，直接合成 RGB32 帧，省去逐帧整屏颜色转换。显示坐标预先计算，重复输出行复用，并用 MXU1 复制到屏幕 RAM 的缓存别名后显式写回。暂停画面和三种模式通过原 RGB565 绘图路径及标量显示路径对照。

68000 的 PGM BIOS、程序及普通 RAM 读取使用独立页表和 MIPS 汇编，普通镜像 RAM 写入也有专用路径；I/O 和跨页长字访问保持原回调。新增精确指令模式匹配的双 RAM 标志等待循环批处理，保留原周期及中断边界，只在两个普通 RAM 值均为零且无待处理中断时启用。启动时在真实 H1 分别对照 1,024 组访存和 1,024 组等待循环，检查完整 CPU 上下文、周期超出量及全 RAM。`h1_pgm_perf` 可选采集 40 Hz 粒度的独占耗时分布，默认关闭。

声音合成降为 8 kHz，并按真实时长调整振荡器步进；设备音频输出沿用原有重采样路径。默认音量 10%。显示使用原始 448×224、4:3 或全屏；暂停菜单和按键设置沿用原有界面。

`tests/pgm_import_host.py` 仅验证生成的非游戏数据和文件转换。`tests/pgm_draw_host.py` 用 160 张生成场景、320 次绘图对照原 RGB565 路径，覆盖翻转、缩放、裁剪、透明行、缓存命中及末尾不完整图块；三种显示模式也对照标量路径。这些主机测试不执行游戏 CPU 或设备模拟。启动、真实画面、输入、MXU、CPU 快速路径和速度以 H1Debug 真实 H1 的记录为准。

## 2026-10-21 真机结果

用户自备的 `kov` V117 已通过真实 H1 启动、投币、开始、进入第一关“截江救阿斗”、移动与攻击、触屏暂停/继续/退出。原始 448×224 与 4:3 显示、PGM/ICS2115 关于页面已检查。测试音量 10%，退出恢复原始 336 MHz，H1Debug 保持运行。

首次转换在 A 盘写入失败后回退 B 盘，包含完整读回校验共 14,858 个 40 Hz tick，约 371.45 秒；生成 67,305,856 字节缓存。再次选原 ZIP 直接复用缓存。全部页 CRC 表和各区头与 PC 参考一致，额外抽样 145,792 字节；未通过 USB 下载整份缓存重新计算 SHA256。

在 408 MHz、4:3、跳1帧、8 kHz 合成下，第一关的一个 19.95 秒战斗窗口记录 226 个逻辑帧、113 个显示帧，即 **11.33 / 5.66 FPS**。最初逐像素查缓存的版本在另一个第一关窗口为 7.94 / 3.97 FPS；两次不是相同状态的确定性重放。当前仍明显卡顿，声音有断续，尚不适合正常速度游玩。

保留的原绘图实现可通过 `h1_pgm_draw_probe` 在本应用暂停菜单中进行冻结帧对照。已记录开场、关卡过渡和两张战斗帧，整张 448×224 画面像素差异均为 0。计时粒度为 25 ms；其中一张战斗帧原路径 7 tick、优化路径 4 tick。此结果不等同于全游戏满速或所有缩放组合均已验证。

同一份 BDA 已覆盖安装到原街机应用位置，并用现有《拳皇97》缓存回归。在未暂停的 10.025 秒演示流程窗口中，记录约 59.15 逻辑帧/秒、29.53 显示帧/秒；这不是完整战斗或全游戏性能保证。最终正常返回桌面，恢复 336 MHz，按键和触屏均已释放，H1Debug 服务保持运行。

源 ZIP 的 H1 副本曾有一个字节拷贝错误。电脑原文件全成员校验通过；核对 H1 整份文件 CRC 后，仅按已确认的原字节修复，并重新核对整份 ZIP 的 CRC。游戏和 BIOS 字节不随仓库分发。

## 同日后续优化

后续 BDA SHA256 为 `c703aac278ab0ec918f6fabb9e694d5747d10f98111c900553f0f7be66700622`。408 MHz、4:3、跳1帧、8 kHz、音量10%的设置保持不变，直接复用原 B 盘缓存。播放页/区 CRC 和页 CRC 表读取已去掉；文件格式及首次 ZIP 转换检查独立保留。

初次进入关卡的一段 20.05 秒窗口含黑屏过渡和图形缓存建立，仅 24.44 / 12.22 FPS，不作为稳定战斗数据。随后两段战斗窗口分别为 34.76 / 17.41 FPS（开启采样）和 38.95 / 19.45 FPS（关闭采样、20 秒）。此前原版战斗窗口为 11.33 / 5.66 FPS；窗口不是确定性重放，不能把提升单独归因于 CRC 或某一项优化。当前仍未达到 60 逻辑帧、30 显示帧的目标，声音仍有断续。

20 秒采样的每逻辑帧独占耗时近似为：68000 4.1 ms、Z80 2.3 ms、声音合成 0.2 ms、背景 2.2 ms、精灵/文字 8.4 ms、LCD 输出 6.9 ms、文件读取 1.2 ms、PCM 0.1 ms，其余输入/清屏/等待等 3.3 ms。采样粒度为 25 ms，通过长窗口累计；这是墙上时间分摊，不是精确 CPU 周期。

真实 H1 上通过 13,056 项原有启动检查及新增的 1,024 项 PGM 访存、1,024 项等待循环检查。开场及两张战斗冻结帧的 RGB32 颜色均与原 RGB565 路径展开后的颜色一致，三种显示模式也与标量输出逐像素一致。最终检查的两张战斗画面，原参考路径分别用 5 和 4 tick，优化路径均为 1 tick；只代表这些画面及顺序测试时的缓存状态。

同一最终 BDA 用现有《拳皇97》缓存回归，10.025 秒的开场至排行流程窗口约 59.15 / 29.53 FPS；不是战斗或全游戏性能保证。PGM 本次整个会话累计 311 次音频欠载、0 次音频调用失败，包含启动、暂停测试及慢速游玩，不能当作单个战斗窗口的计数。最后正常退出到桌面，恢复 336 MHz，释放按键和触屏，H1Debug 保持开启。

## 精灵分项与汇编 / MXU 优化

新 BDA SHA256 为 `15376388c1985bf141687ad8d05228e9e16985065bdb3688c3b3ecc2b5869ae1`。`h1_pgm_perf` 升为版本2，独占 tick 数组扩为12项：其余、68000、Z80、声音合成、背景、精灵参数/缩放准备、LCD、文件读取、PCM、精灵缓存未命中解码、精灵像素合成、文字。透明判断、调色板寻址和像素写入保留在同一个合成循环中，避免逐像素插入计时本身成为主要开销。

未水平缩放的精灵直接顺序或反向读取解码索引，省去每像素的列映射；缩放精灵保留原列映射。新增四像素展开的 MIPS32 行合成，以及 MXU1 `S32LDDV` 调色板查表与 RGB32 写入版本。可通过 `h1_pgm_sprite_mode` 对照原列映射 C（0）、顺序/反向 C（1）、MIPS（2）、MXU（3，默认）。索引255仍透明，调色板变化、裁剪及翻转均保留。

按用户要求，PGM 的三个 MXU 精灵叶函数及屏幕复制函数不主动关闭/恢复中断；它们保存恢复使用的 XR 和 MXU_CR，不包含 CP0 指令。原有 Neo Geo MXU 绘图函数保持原机器码及中断处理。构建审计检查实际链接的 MXU1 指令并拒绝新 PGM 叶函数中的 CP0 操作；同时修复了生成的 MXU 汇编仅含 `.include` 路径而导致构建缓存未跟随被引用内容更新的问题。

真实 H1 通过新增的3,072组行合成测试（顺序、反向、列映射，MIPS/MXU各512组）与256组MXU复制测试，覆盖透明度、尾部、不同对齐、调色板变化和边界；原有PGM访存及等待循环各1,024组也通过。两张不同战斗冻结帧均与原RGB565参考颜色一致，三种显示模式差异为0。主机仅运行生成图形的640次C路径对照，不执行MIPS、MXU或游戏CPU模拟。

在两张冻结战斗帧上，各模式预热后重复完整绘图128次，40 Hz原始tick分别为：原C 119/120、顺序或反向C 113/113、MIPS 109/110、MXU 109/109。平均每张绘图由约23.24/23.44 ms降到21.29 ms，减少约8.4%/9.2%；不包含游戏CPU及LCD输出。MXU与普通MIPS的差距在本次测量中很小，不能宣称额外大幅提速。

408 MHz、4:3、跳1帧、8 kHz、音量10%下，20.025秒战斗采样窗口为40.25/20.12 FPS（逻辑/显示）。每逻辑帧近似：精灵参数准备未采到tick、缓存解码0.06 ms、精灵像素合成3.66 ms、文字1.40 ms、背景3.75 ms、LCD 4.56 ms、68000 4.90 ms、Z80 2.98 ms，其余输入/清屏/等待等2.98 ms。零tick不表示零耗时；计时刻度为25 ms，使用长窗口累计。该窗口可见精灵均走无水平缩放路径；缩放映射由原生行测试的重复/跳列及主机生成图形对照覆盖，不能视为所有真实游戏缩放组合均已验证。

另一个关闭采样的19.975秒战斗窗口为40.85/20.43 FPS，仍未达到60/30目标。不同实时窗口不是确定性重放，收益以同一冻结帧的四模式对照为准。测试结束正常退出到桌面、恢复原336 MHz并释放输入，H1Debug保持运行；本轮未再次运行Neo Geo游戏回归。
